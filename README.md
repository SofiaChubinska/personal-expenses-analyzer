## Запуск на Windows

Відкрийте термінал у розпакованій папці проєкту й виконайте команди.

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

Відкрийте [http://127.0.0.1:8000](http://127.0.0.1:8000). Для CSV достатньо Python 3.10 або новішого. У Linux/macOS використовуйте `python3` для створення середовища та `.venv/bin/python` для команд запуску.

## Дані й прогноз

- CSV у UTF-8 з роздільником комою або XLSX. У XLSX читається активний аркуш. Заголовки: `date,description,amount,currency`. Дата у форматі `YYYY-MM-DD` або клітинка типу «дата» в Excel. Сума невід’ємна, з точністю до двох знаків, валюта — трилітерний код.
- Необов’язкове поле `category` задає категорію. Якщо воно порожнє, застосунок визначає її за описом. Суми агрегуються окремо за валютами.
- `data/example.csv` містить 8 наданих операцій. `data/demo_history.csv` додає 30 синтетичних операцій для перевірки прогнозу. Файл обробляється локально під час запиту і не записується на диск вебзастосунком.
- Прогноз — середнє сум за три послідовні місяці. Позначте «Останній місяць неповний», щоб виключити його з навчального вікна. Прогноз тоді відповідає місяцю після останнього повного місяця. Порожні місяці не вважаються місяцями з нульовими витратами. MAE обчислюється лише для місяців, перед якими є три послідовні спостереження.
- Базовий асистент відповідає за обчисленими підсумками. Приклади запитань для захисту — «Яка загальна сума витрат?», «Яка найбільша категорія?», «Який прогноз?», «Що можна скоротити?».

## Мовна модель Ollama

Для генеративних відповідей встановіть Ollama, завантажте сумісну локальну модель, наприклад `ollama pull qwen2.5:3b`, і запустіть Ollama. Скопіюйте `.env.example` у `.env` та вкажіть `OLLAMA_MODEL=qwen2.5:3b`. Перезапустіть застосунок і поставте запитання. У відповіді має відобразитися режим «Ollama». Асистент передає локальній моделі підсумки та до 20 останніх операцій вибраної валюти. Якщо модель недоступна, він переходить до відповідей за правилами.

## MongoDB Atlas і семантичний пошук

`atlas_ingest.py` — вихідний модуль імпорту й пошуку. Він запускається окремо від локального дашборда. Встановіть `requirements-atlas.txt`. У локальному `.env` вкажіть новий `MONGODB_URI` та `MONGODB_DB`. Для першого запуску векторизації знадобиться доступ до Hugging Face для завантаження моделі. Потрібен Atlas із підтримкою Vector Search та правом створювати пошуковий індекс.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-atlas.txt
.\.venv\Scripts\python.exe atlas_ingest.py init
.\.venv\Scripts\python.exe atlas_ingest.py import data/example.csv
.\.venv\Scripts\python.exe atlas_ingest.py search --query "оплата електроенергії" -n 5
```

Команда `init` ініціює створення індексу. Перед пошуком перевірте його готовність в Atlas. CSV, TXT і PDF із текстовим шаром підтримуються в окремому імпортері. Чанки зберігаються в `chunks`, метадані та текст джерел — у `documents`, локальні копії — у `data/raw/`. Дашборд обчислює фінансові суми за повним вибраним файлом. Атласний пошук повертає релевантні фрагменти для пошуку за змістом.

## Файли

- `app.py`, `index.html`, `dashboard.js`, `style.css` — локальний вебзастосунок.
- `expenses.py`, `categories.py` — імпорт, категоризація, статистика, прогноз і сценарій економії.
- `assistant.py` — відповіді за правилами та підключення локальної моделі.
- `atlas_ingest.py` — початковий імпортер документів і векторний пошук.
